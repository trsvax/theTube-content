DRAFT

The platform has a POSIX surface. Not because someone planned it — because files at URLs is what a filesystem looks like when the kernel is a CDN.

## The syscalls

| Syscall | Platform | What happens |
|---|---|---|
| `open()` | `POST /w/open?ns={ns}` | Get a token. Checks permissions. Returns a scoped handle. |
| `write()` | `POST /w/{ns}/{verb}?...` | Write data. Token required. 202 = accepted. |
| `read()` | `GET /{path}` | Fetch a file. Cached at the edge. |
| `readdir()` | `GET /{path}/index.json` | List a directory. Static file or Lambda-generated. |
| `stat()` | `HEAD /{path}` | Metadata. Last-Modified, Content-Length, ETag. |
| `close()` | Token expires | Implicit. No explicit close. |
| `unlink()` | `POST /w/{ns}/delete?...` | Soft delete. Writes a tombstone. Log has history. |
| `chmod()` | IAM + CloudFront behaviors | Change who can access a path. |
| `fork()` | New repo | Isolated process. Own namespace, own Lambda, own permissions. |

## open() is sudo

Everyone starts with read access. `open()` is how you escalate.

Anonymous? You get a low-trust token. Logged in? Higher trust. Passkey? Admin. Same call, different result based on who you are. The system reads your cookies and returns the capability you've earned.

The token is a file descriptor. It carries: which namespace, what permissions, how many uses, when it expires. The processor validates the descriptor, not the client's intent.

## write() is POST

```
POST /w/comment/add?page={uuid}&body=hello&token={token}
```

The `?` means the data is self-contained in the URL. The cheapest handler (log and 202) is sufficient. No compute required. Data never lost.

No `?` means the data is in the body. Requires Lambda. Might 503. You opted into compute — you accept the failure mode.

POST because CloudFront must not cache writes. Every request hits the function. Every request gets logged.

## readdir() is index.json

Every directory has an `index.json`. That's `ls`. The convention is universal.

```
/                          → /index.json (lists sections)
/public/                   → /public/index.json (lists posts)
/comments/{uuid}/          → /comments/{uuid}/index.json (lists comments)
/books/tapestry-nocode/    → /books/tapestry-nocode/index.json (lists chapters)
```

Behind the URL: a static file (generated by a build or processor) or a Lambda (computed on read, merges checkpoint + new files). The client doesn't know which. The implementation is invisible.

## append() is mkdir

S3 doesn't have append. But you don't need it. "Append to a collection" is "create a new file in the directory." Each entry is its own file. The directory grows. `index.json` reflects the growth.

```
/comments/{uuid}/abc.json   ← first comment
/comments/{uuid}/def.json   ← second comment (this is "append")
```

No read-modify-write. No race conditions. Just create.

## The kernel

CloudFront is the kernel. It:

- Routes URLs to implementations (S3, Lambda, cache)
- Enforces permissions (signed cookies, Lambda@Edge auth)
- Rate limits (WAF)
- Caches (TTL per behavior)
- Logs everything (access logs = the journal)

The client talks to the kernel. The kernel decides what happens. Static file? Lambda? Cached response? The client doesn't know. The kernel handles it.

## Compute is pluggable

Any URL can be backed by a static file today and a Lambda tomorrow. The interface never changes. Static is the default. Lambda is the upgrade.

```
/comments/{uuid}/index.json
  Today: S3 file, regenerated by processor
  Tomorrow: Lambda merges checkpoint + new files on read
  Client code: unchanged
```

The upgrade path is always: same URL, smarter backend. No client changes. No API versioning. No migration.

## Isolation is fork()

Each namespace is a process. Own repo, own Lambda, own IAM, own S3 prefix. Can't touch other namespaces.

```
/w/comment/*  → comment repo → comment Lambda → s3://bucket/comments/*
/w/contact/*  → contact repo → contact Lambda → s3://bucket/contact/*
```

A bad deploy breaks one namespace. Everything else keeps working. Blast radius = repo scope. That's `fork()` — isolated address spaces with no shared memory.

## The log is the journal

Every write is logged. The log is immutable, append-only, and the source of truth. Files on S3 are a projection — a materialized view rebuildable from the log.

This is a journaling filesystem. The journal (CloudFront access logs) records every operation. The filesystem (`/comments/`, `/public/`, etc.) is derived from it. Corrupt the filesystem? Replay the journal. Full recovery.

## What this means

The platform isn't *like* an operating system. It *is* one. The abstractions map because the problems are the same: naming, permissions, isolation, persistence, caching. The web solved them with URLs, cookies, repos, S3, and CDNs. Same solutions, different names.

`man 2 open` — get a capability.
`man 2 write` — use it.
`man 2 readdir` — see what's there.

The rest is implementation details.
